# بوّابة MAB (MAB Portal) — الخطة المعمارية

منصّة واحدة تجمع كل أنظمة MAB (زي جسر): دخول موحّد بإيميل + كود، وقائمة أنظمة
على اليمين تظهر **حسب صلاحيات كل مستخدم** التي يحدّدها الـIT. تطبيق **جديد
مستقل تمامًا** — لا يلمس أي نظام قائم.

## المبدأ: العزل التام
- البوّابة تطبيق منفصل، قاعدة بياناته الخاصة، حساباته الخاصة.
- الأنظمة الحالية (التقييم، التصاريح، الميكا، التاسكات، التكتات) تبقى **كما هي**.
- الربط الوحيد المستقبلي = مسار `/sso` **صغير ومعزول** يُضاف لكل نظام (يُجرَّب على
  نسخة قبل الأصل). لا إعادة كتابة، لا مساس بباقي النظام.

## التقنية
Next.js (App Router) + Prisma + PostgreSQL + Tailwind — نفس ستاك التقييم/الميكا،
ونعيد استخدام نفس بنية البريد (Microsoft Graph) والكود (login challenge).

## الدخول الموحّد (بلا كلمة مرور)
1. المستخدم يكتب إيميله → إن كان مسجّلًا ونشطًا، يُرسَل كود ٦ أرقام (Graph).
2. يُدخل الكود → تُفتح جلسة البوّابة (كوكي httpOnly، JWT قصير + refresh).
3. لا كلمات مرور إطلاقًا — أبسط وأأمن.

## الشاشة الرئيسية (Launcher)
- شريط علوي: شعار MAB + اسم المستخدم + خروج.
- **يمين: قائمة الأنظمة** التي يملك المستخدم صلاحية رؤيتها.
- الضغط على نظام → تتوسّع **روابطه الفرعية** تحته بشكل مرتّب.
- الضغط على رابط → فتح النظام عبر **SSO** (دخول تلقائي بضغطة واحدة).

## الدخول الموحّد للأنظمة (SSO handoff)
عند فتح نظام: البوّابة تُصدر **توكن JWT قصير جدًا (~٦٠ ثانية)** موقّعًا بسرّ مشترك،
يحوي: `{ email, name, systemKey, exp }`، وتحوّل إلى:
`{system.baseUrl}{system.ssoPath}?token=…`

مسار `/sso` في كل نظام (إضافة معزولة):
1. يتحقّق من توقيع التوكن + صلاحيته + أنه لهذا النظام.
2. يجد مستخدمه الداخلي **بنفس الإيميل** (كل الأنظمة تستخدم الإيميل مفتاحًا).
3. يفتح **جلسته الداخلية** المعتادة، ويحوّل لصفحته الرئيسية.

بهذا: هوية البوّابة مركزية، وكل نظام يحتفظ بمستخدميه وصلاحياته الداخلية كما هي.

## الصلاحيات (يحدّدها الـIT لكل مستخدم)
- البوّابة تدير **«من يرى أي نظام»** فقط (بلاطات/قائمة). لا تمسّ RBAC الداخلي لكل نظام.
- `UserSystemAccess`: صف لكل (مستخدم × نظام) مسموح له.
- `isSuperAdmin` (IT): يرى كل الأنظمة تلقائيًا.
- لوحة IT في البوّابة: قائمة المستخدمين + تبديل الأنظمة لكل مستخدم.

## نموذج البيانات (مختصر)
- `PortalUser` — هوية البوّابة (email فريد، name, isActive, isSuperAdmin).
- `System` — دليل الأنظمة (key فريد، name, icon, color, baseUrl, ssoPath, order).
- `SystemLink` — الروابط الفرعية تحت كل نظام.
- `UserSystemAccess` — أي مستخدم يرى أي نظام (يديره IT).
- `LoginChallenge` — كود الدخول (نفس نمط التقييم).
- `RefreshToken` — جلسة البوّابة.

## المراحل
1. **الأساس (الآن):** المخطط + سكافولد التطبيق (معزول، ما يمسّ شيئًا).
2. الدخول الموحّد (إيميل + كود) + الجلسة.
3. الـLauncher (قائمة الأنظمة حسب الصلاحيات + التوسّع).
4. لوحة IT (مستخدمون + منح الأنظمة لكل مستخدم).
5. توكن SSO + مسار `/sso` على **نسخة** من كل نظام (تجربة) ثم الأصل.
6. nginx على نفس الدومين (`/` بوّابة، مسارات الأنظمة).

## قرارات مثبّتة
دخول واحد (SSO) · نفس الدومين · هوية جديدة · نسخ للأنظمة أولًا · صلاحيات لكل مستخدم (IT).
